# monju-advisor

Claude Code の回答が終わるたびに、Haiku が第三者の目でやり取りを読み、人と Claude の前提のずれを見つけて、ステータスラインに一言で知らせる mod です(三人寄れば文殊の知恵)。
人の書き方にも助言し、良い書き方なら褒めます。Claude が人に答えてほしい問いを出したときは、入力欄に問いごとの答える枠を足します。
送信は止めず、遅らせもしません。
その代わり、回答のたびに Haiku を1回呼ぶので、その分の利用量が増えます。一言は回答の数秒後に出て、外れることもあります(下の「分かっている限界」)。

## 見る観点

| 観点 | 例 |
|---|---|
| 問いへの答え漏れ | Claude が3つ聞いたのに、1つにしか答えていない |
| どれを指すか分からない答え | 「それで」「いい感じで」だけで、どの案か決まらない |
| 書かれていない前提 | 対象の環境・範囲・既存の書き方を書いていない |
| 方針を変えたのに、前の方針での変更が残っている | 「A でなく B で」と言ったが、A で直したファイルが戻されていない |
| 人が手で変えたことを Claude が知らない | 人がファイルを直したのに、Claude は前の中身のつもりで進める |
| Claude が推測のまま進めた | 「〜と思われます」と言いながら、確かめずに実装を始める |
| Claude が解釈を示さずに曖昧な依頼を進めた | 「直して」に対し、どこをどう直すか言わずに変更する |
| 頼まれていない範囲まで変えた | 1か所の修正のはずが、周りの書き換えまで入っている |
| 質問を指示と受け取った | 「なんでこうなってる?」に、答えずに直し始める |
| Claude が黙って手段を変えた | 決めた方法が通らず、別の方法に切り替えて進める |
| 否定が続く | 「違う」「そうじゃない」が続く |
| 同じ所の直しを繰り返している | 同じファイルで何往復もしている |
| 会話が長くなり、最初の決定が埋もれている | 序盤に決めたことを Claude が守らなくなる |
| プランモードの方がいい | 設計や大きな変更を、通常モードのまま頼む |
| 一度に頼む量が多い | 別々の作業を1回にまとめて頼む |
| 前の作業と関係ない話を同じ会話で始める | 作業の途中で、別件の依頼をする |
| もっと伝わる書き方がある | 「エラーの全文を貼ると早い」 |
| 良い書き方を認める | 目的・範囲・確かめ方が書けている、問いに番号で全部答えている |

- 一番大事なずれを1つだけ選んで一言にします
- 「OK」「2で」のような短い返事は、前の問いへの答えとして通じるなら指摘しません
- 別々の作業が並んだ発言なら、「一度に頼む量が多い」を優先します
- 「プランモードの方がいい」は、通常モードのときだけ見ます

基準の文は [monju-advisor/hooks/judge.ts](monju-advisor/hooks/judge.ts) の `RULES` にあります。

## 何をするか

on の間、回答が終わるたびに Haiku を1回呼び、返事で次のようにします。

| 返事 | どうなるか |
|---|---|
| ずれがある | ステータスラインに `monju: <一言>` を出す |
| ずれは無く、書き方が良い | ステータスラインに褒める一言を出す |
| ずれも褒める所も無い | 何も出さない。前の一言が残る |
| 回答の中に、人が答えないと Claude が進めない問いがある | 入力欄に `1. <問いの要約>:` を問いの数だけ足す |

- 一言は友達のような距離感で、言葉づかいは丁寧です。60 字以内にするよう頼んでいますが、コードでは切りません
- 一言は、次の一言が出るまで残ります
- 枠は、打ちかけの文があれば、その後ろに改行してから足します。打った文は消しません
- 返事が来る前に次の発言を送っていたら、一言は出しますが、枠は入れません
- AskUserQuestion のダイアログの問いは枠にしません。回答の文の中の問いだけです
- 「ほかに作業はありますか?」のような軽い問いは、枠にしないよう頼んでいます

## 使い方

```
/monju-advisor on    # 始める(入れた直後は on)
/monju-advisor off   # やめる。off の間は Haiku を呼ばない
/monju-advisor       # 今の状態を表示する
```

on / off は次のセッションにも残ります。

| ステータスラインの表示 | 意味 |
|---|---|
| `monju-advisor: on` / `monju-advisor: off` | セッションの始めと、切り替えたときの状態 |
| `monju: <一言>` | 直前の回答のあとの助言。次の一言が出るまで残る |

## 見ないターン

次のターンでは Haiku を呼びません。

- off の間
- Esc などで中断したターン
- バックグラウンドの作業の完了通知(`<task-notification>` で始まる入力)と、人が打ったのではない Claude Code の入力
- スラッシュコマンド
- サブエージェントの作業(ツールの回数や編集したファイルにも入れません)

## Haiku に渡す量と呼ぶ回数

- 呼ぶのは、on の間、回答が終わったとき1ターンにつき1回です。送信時には呼びません
- 渡すのは次のものです。空のものは入れません。多いときで約 3700 字です

| 渡すもの | 量 |
|---|---|
| 今回の発言 | 先頭 1000 字 |
| 今回の回答 | 末尾 800 字 |
| 前の回答 | 末尾 400 字 |
| 往復の数・今のモード | - |
| このターンのツール名と回数 | - |
| Claude が Edit・Write で編集したファイルと、セッションでの編集回数 | - |
| Claude の編集の後に手で変わったファイル | - |

- 返事は最大 400 トークン、待つのは 10 秒までです。過ぎたら、そのターンは何も出しません
- 回答は待たせません。一言は回答が終わってから数秒後に出ます(作者の環境で約 3〜4 秒。試しで数回測った値)

## 分かっている限界

- 手で変わったかは、Claude が Edit・Write で編集した直後の更新時刻と、次の回答後の時刻を比べて見ます。Claude が編集していないファイルの変化は見えません
- Claude が Bash(sed など)で、Edit・Write で一度編集したファイルを変えると、手で変わったと見えることがあります(推測)
- モードは発言の後に届く印で覚えるので、モードを切り替えた直後のターンは前のモードで見ることがあります
- 判定の精度は追い込んでいません。作者が試した 12 件の例では、10 件で指摘の中身が合いました。外れは使いながら集めて直します
- 回数や履歴は残しません

## 入れ方

このリポジトリをマーケットプレイスとして登録して入れます。

```
claude plugin marketplace add AndoYuto87/monju-advisor
claude plugin install monju-advisor@monju-advisor
```

入れた直後は on です。止めたいときは `/monju-advisor off` にします。

## テスト

リポジトリの直下で:

```
claude plugin validate ./monju-advisor
claude plugin test ./monju-advisor
```
